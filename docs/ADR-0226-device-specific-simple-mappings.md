# ADR-0226：设备专属 Simple 映射

问题：当前选中profile.devices非空一律拒绝，Linux已有可信物理DeviceInstanceId/generation与带TTL的vendor/product上下文，现有Simple mapping也已有条件求值与Down保存绑定。无需引入第二套设备匹配模型。

依据固定ec2fea8940f7254a748c052a890ee9db7113d9b1：src/apps/CoreService/include/core_service/daemon/device_grabber_details/simple_modifications_manipulator_manager.hpp先按device数组顺序加入device.simple_modifications并附device_if，再加入profile全局simple。src/share/manipulator/condition_factory.hpp的make_device_if_condition从device.identifiers只取四项；src/share/types/device_identifiers.hpp初始化缺省ID为0、两类bool为false。不运行上游macOS代码。

选择：将每项设备映射编为现有Simple Mapping，添加Condition::Device{unless:false,exists:false}，设备项顺序优先于全局Simple，不新增阶段。复用复杂条件的严格DeviceProperties标识解析，避免两套字段/范围规则；与上游相同，profile设备标识规范化为vendor/product缺省0、is_keyboard/is_pointing_device缺省false四个明确约束；不将空对象当通配。此特定selector按上游忽略location/address/其他类型字段，raw仍保留；复杂device_if条件仍使用其全部显式字段。capabilities.reliable_device_identity是编译gate：Windows Hook继续拒绝，不能猜RawInput与Hook事件关联。当前Linux Runtime尚未提供is_keyboard/is_pointing_device事实，因此该selector在仅有vendor/product的生产上下文中不会匹配。此为编译/控制器接线，不能声称Linux每设备配置已可用；须接入可信类型provider。Linux没报告的属性保持Unknown，过期/缺上下文不让设备专属条件成立；可退到全局映射。按住后继续保存旧binding/Arc，即便context改变、过期或热重载，也不重匹配Up/Repeat。

每个device按整体准入；未知功能设置、非空Fn映射、ignore:true等不实现的捕获/硬件行为仍拒绝且不编入该设备的部分映射。明确ignore:false及部分明确false的禁用开关是无操作值；不把任意未知false当无操作。最多256device项，所有实际映射共享既有4096规则预算。raw全量保留、诊断定位原始/devices/i路径。每个已编入映射的设备附KW-DEVICE-001 Warning，明确fresh trusted类型事实与缺失/过期全局回退边界；warning不意味着已运行或provider ready。

测试需经过真实JSON编译→两种执行模式，验证设备优先/全局回退、不同generation、未知/过期上下文、旧Arc热更新与释放、缺失能力及未知设置拒绝。Linux完整冷准备和Windows拒绝分别验证。无实际设备/注入，不据此宣称Windows每设备或Linux所有标识属性可用。GUI设备表、ignore/LED/Fn、自动设备发现与原生硬件验收后续完成。
